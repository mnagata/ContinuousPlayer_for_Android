# ContinuousPlayer — 現行実装仕様書

本書は画面・操作・再生・保存・通信・音声出力の詳細仕様と実装構成をまとめる。リポジトリ内の実装・リソース・ビルド設定に基づき、未実装の構想や実機検証済みであることを示すものではない。機能・動作環境・基本的な使い方は [README](../README.md) を参照。

実装照合日：2026-09-28。未コミットの実装も含む作業ツリーを対象とする。

2026-10-27更新：ホームの「その他」とアプリ内終了を廃止し、アプリの終了をOSに委ねる仕様へ変更。

## 1. 概要と動作環境

TVアニメのOP/EDを中心に、選択したフォルダーの動画・音声ファイルを連続再生するAndroidアプリ。スマートフォン・タブレットとAndroid TVで同一APKを使用する。

| 項目 | 現行設定 |
|---|---|
| アプリ名 / applicationId | ContinuousPlayer / jp.nagu.continuousplayer |
| 最低OS | Android 14（API 34） |
| compileSdk / targetSdk | 36（minorApiLevel 1）/ 36 |
| versionCode / versionName | 1 / 1.0 |
| 構成 | 単一 `:app` モジュール、Kotlin、XML View |
| Gradle / Android Gradle Plugin | 9.6.1 / 9.4.0 |
| Gradle Daemon JVM / コンパイル出力 | JDK 21 / Java・Kotlin JVM 11 |
| 再生基盤 | Media3 ExoPlayer + MediaSession |

バージョンの参照元は `app/build.gradle.kts`、`gradle/libs.versions.toml`、`gradle/wrapper/gradle-wrapper.properties`、`gradle/gradle-daemon-jvm.properties`。

## 2. 起動と画面遷移

```text
アプリ起動 → システムスプラッシュ → 初期画面
初期画面「OP / EDを選ぶ」
  → 登録数・保存先を問わず「保存済みフォルダー」を表示（0件では「フォルダーを追加」へフォーカス）
  → 保存済み行を選んで開く、または「フォルダーを追加」で再生元を選ぶ
  → 端末 / SAF：フォルダーのアクセス許可 → 保存済み一覧の登録行へ
  → TVのUSB：未許可ならOS設定 → USBブラウザー → 登録 → 保存済み一覧の登録行へ
  → NAS / DLNA：サーバー探索 → 公開階層 → 登録 → 保存済み一覧の登録行へ
  → ファイル選択 → 選択位置から連続再生
再生画面「戻る」/ Esc / O /「ファイル一覧」 → 再生セッションを一時保持してファイル一覧
  → キャンセル：元のファイル・位置・再生意図へ復元（割り込み後は一時停止）
再生画面「ホームに戻る」 → 再生を終了 → ホーム
初期画面「戻る」 → OS標準の戻る処理
```

通常起動ではファイルピッカーを自動起動しない。初期画面のボタンから選択を開始する。SAFのシステムピッカーをキャンセルした場合は結果がnullのため処理を進めず、その下に維持していた追加先選択ダイアログへ戻る。USBで成功した閲覧位置を保存する。「このフォルダーを登録」で現在のフォルダーを保存済み一覧へ登録し、その行を選択・表示する。登録だけでは再生しない。

### 2.1 スプラッシュ画面

- Android標準の `android.window.SplashScreen` APIを使用。互換ライブラリや専用Activityは追加していない。
- Manifestで `MainActivity` に `Theme.ContinuousPlayer.Starting` を指定。
- 背景は濃紺 `#101743`、中央マークは `@drawable/ic_launcher_foreground`。
- `windowSplashScreenBehavior=icon_preferred`。
- `onCreate()` の `super.onCreate()` より前に通常テーマへ切り替える。
- TV以外では終了時に180msのフェードアウトを行い、終了後にスプラッシュViewを削除する。
- TVでは独自の終了アニメーションを登録せず、システムの起動演出に従う。
- 最低表示時間や意図的な待機時間は設定していない。

## 3. 初期画面

`activity_main.xml` の `folder_select_container` を表示する。

| 要素 | 表示・動作 |
|---|---|
| 背景 | 濃紺を中心にシアン系・紫系をつないだグラデーション |
| ロゴ | ランチャーアイコンの前景ベクターを共用。装飾としてアクセシビリティ対象外 |
| 画面名 | ホーム。読み上げのペイン名も同じ |
| アプリ名 | ContinuousPlayer、白、1行、自動文字サイズ調整12〜32sp |
| メインボタン | 「OP / EDを選ぶ」、通常幅280dp・最小高さ56dp、青緑〜紫のグラデーション |
| TV操作ガイド | TV端末のみ表示。再生中は左右で前後ファイル・上下で±10秒・決定で再生/一時停止、一時停止中は方向キーでボタン選択・決定で実行と案内 |
| キャッチコピー | 表示しない |

- 内容は中央揃えの縦配置。ScrollViewで狭い横画面などでもスクロール可能。
- 左右余白は28dp。通常はロゴ180dp・上下余白32dp、横画面ではロゴ100dp・上下余白20dp。
- TVでは初期画面表示時に「OP / EDを選ぶ」へフォーカスする。
- 選択・押下状態は専用ボタン背景で区別。ホームの操作ボタンは「OP / EDを選ぶ」のみとし、方向キー・Tabで削除済みのボタンへ移動しない。
- 再生画面と異なり、初期画面ではシステムバーを表示する。
- ホームの選択ボタンはwrap_contentと幅の上限を使い、狭い画面の利用幅に収める。文字拡大時は高さを広げて折り返す。
- アプリの終了はOSに任せる。Android・Android TVとも、ホームの「その他」ボタンとアプリ内の終了メニュー・終了ボタンを設けず、アプリ独自のタスク削除は行わない。ホームの戻る操作はOSの通常動作へ渡す。保存済みフォルダー行の「その他」→「登録解除」は維持する。

## 4. 再生画面

黒背景の `player_container` 内に以下を配置する。

| 要素 | 仕様 |
|---|---|
| PlayerView | 全画面、Media3標準コントローラは無効、ローディングアイコンは非表示 |
| touch_overlay | 全面の透明Viewでタップ・スワイプを受ける |
| pause_overlay | 上端、暗色の半透明背景。共通操作・ファイル名・再生操作の3行。表示／非表示でPlayerViewの領域を変えない |
| portrait_video_info | 縦画面のみ、下端から120dpの位置にメディア情報を表示 |

ステータスバーとナビゲーションバーを隠し、スワイプによる一時表示を許可する。再生画面でウィンドウフォーカスを取り戻したときもシステムバーを隠す。プレイヤー生成中は `keepScreenOn=true`、プレイヤー解放時に解除する。

### 4.1 操作部

ユーザーによる一時停止・背景化後の手動再開待ちに加え、音声のみのメディア、最終終了、再生エラー、OSのタッチ探索が有効な間は操作部を表示する。情報・ファイル選択の表示中とバックグラウンド中は隠し、閉じた後や復帰後はその時点の条件で再評価する。ポインターによる一時表示は5.3の条件でも管理する。

音声のみの判定は再生エンジンのトラックに音声があり映像がないことを使い、拡張子では決めない。同じメディアでバッファリング等によりトラックが一時的に空になっても判定を維持し、メディアが切り替わったら再判定する。動画のバッファリングだけでは一時停止用の操作部を出さない。isPlayingではなくplayWhenReadyを再生意図として使用する。

最終ファイルの自然終了では「最後まで再生しました」、playerErrorが残っている間は「再生できませんでした」の状態行をファイル名の下に表示する。状態行はpoliteのライブ領域とし、通常再生に戻れば隠す。終了状態の再生操作は同じ最終ファイルの0秒から再開する。全環境の再生エラーは同じ項目で一時停止する。再試行位置・復旧操作の統一はD26の修正対象とする。

再生ボタンのアイコン・読み上げ名・ツールチップは、再生意図がある通常状態（バッファリングを含む）では「一時停止」、一時停止・終了・エラーでは「再生」にする。OSのタッチ探索の有効／無効の通知を受けて表示を更新し、動画再生中も標準の画面ボタンへ到達できるようにする。TVでは一時停止・終了・エラー時に再生ボタンへフォーカスし、再開後は音声の操作部が表示されたままでも再生領域へフォーカスを戻す。タッチ探索中は再開時のフォーカスを強制移動しない。

通常は3行に分け、終了・エラー時はファイル名と下段の間に状態行を追加する。ファイル名や状態文の長さでボタンを押し出さない。

1. 上段48dp：ホームに戻る → ファイル一覧 → メディア情報。左右キーはこの3ボタンを循環し、Tabはメディア情報の次に下段へ進む。再生画面の終了ボタンは置かない。
2. ファイル名：独立した1行、中央省略、中央揃え。文字倍率に合わせて行の高さを確保する。読み上げ用の文字列は省略しない。
3. 下段56dp：前のファイル → 10秒戻す → 再生／一時停止 → 10秒進める → 次のファイル。5つの48dpボタンを中央に並べる。

追加した前後・±10秒ボタンはPlayerControllerの既存処理を使い、playWhenReadyを変えない。ファイルの変更に合わせて表示名を更新する。前／次はプレイリスト内の隣接項目と対応コマンドがある場合だけ有効。±10秒は現在項目がシーク可能で、対応コマンドがある場合だけ有効にする。タイムラインと利用可能コマンドの変更でも再評価し、無効状態は淡色のアイコンで表示する。キー・タッチ・MediaSessionでも8章の共通境界処理を使用する。

ボタンは各48dp、既存と同じ緑色・白枠のフォーカス背景を使う。全ボタンに読み上げ名とツールチップを付ける。左右キーはそれぞれの行内を循環し、上段から下方向は再生ボタン、下段から上下方向は情報ボタンへ移る。Tabは上段の並びから下段の並びへ進み、最後からホームへ戻る。操作後にフォーカス中の前／次ボタンが無効になる場合は再生ボタンへ移す。TVで操作部へ入るときは再生ボタン、再開後はPlayerViewへ戻す。

操作部は映像に重ねるFrameLayout内に保持し、表示／非表示では映像のサイズ・位置を変えない。操作部だけにシステムバー・画面切り欠きの安全領域（表示状態によらない上・左右のInsets）を足し、OSバーの一時表示やノッチにボタンが重ならないようにする。一時停止・手動再開待ち・音声・終了・エラー・タッチ探索の表示を優先し、ポインター移動による表示も加える。

### 4.2 情報表示

縦画面の情報欄には、取得できた項目を表示する。

- 拡張子を除いたファイル名、ファイルサイズ
- 動画コーデック、解像度、フレームレート
- 音声コーデック、サンプルレート、チャンネル数
- 音声出力の概要とミキサー情報

縦画面のサイズ欄は、不明な値を「サイズ不明」と表示する。SAFでもプロバイダーがサイズを返さない場合に該当する。

情報ダイアログは「ファイル」→「映像・音声形式」→「音声出力」の順に見出しを付けて表示する。取得できない値は「取得できません」、機器やアプリの機能として利用できないものは「未対応」、存在しないトラックは「なし」、対応していて優先設定がないミキサーは「未設定」と区別する。項目を空文字や負の値のまま表示しない。

- ファイル：元の名前の全文、サイズ（B／KiB／MiB／GiB等）、再生時間、コンテナーMIME。名前が取得できない場合も共通の未取得表記にする。
- 映像・音声形式：現在の再生エンジンと選択トラックから、映像コーデック・MIME、解像度、フレームレート、音声コーデック・MIME、ソースサンプルレート・チャンネル数を表示する。値がない場合も未取得を明示する。音声のみ・映像のみでトラックが存在しないと確定した場合は「なし」とし、未対応と混同しない。情報表示のためにMediaExtractorで元メディアを開き直さない。
- 音声出力：アプリ自身のAudioTrackで確認した出力経路、AudioTrackの形式・サンプルレート・チャンネル数、Bit-Perfect設定、実際の出力先の優先ミキサーとその設定形式を表示する。接続されているだけの機器を出力先と推測せず、経路を確認できない場合は取得できないと表示する。内蔵スピーカー等、Bit-Perfect設定対象でない出力や対応属性がない出力は未対応とする。

[AudioRouting.getRoutedDevice](https://developer.android.com/reference/android/media/AudioRouting#getRoutedDevice())は再生中だけ有効なため、一時停止前の経路も保持する。[AudioTrackのサンプルレート・形式](https://developer.android.com/reference/android/media/AudioTrack#getSampleRate())はAudioTrackに設定された値として表示し、DACの実測値とは扱わない。Bit-Perfectの「設定済み」も、同じ経路への設定成功と優先属性を示すもので、実出力のビット一致を測定した結果ではない。

「メディア情報」ボタン・INFOキー・修飾なしのIで開く。情報取得より先に、現在のプレイヤー・ファイル・プレイリスト・元フォルダー・秒数・playWhenReadyとフォーカスを一時保持して一時停止する。ファイルとソース形式を直ちに表示し、音声出力の初期値も未取得として表示してから取得後に更新する。出力の取得失敗でも区分や項目を非表示にしない。同時に複数の情報画面を開かない。文字拡大時は本文のスクロール領域を縮めてOKボタンの領域を確保する。

OK・I・Esc・戻る・その他のダイアログ終了は、一覧キャンセルと共通の復元処理を使う。元が再生中なら同じ位置から再開し、元が一時停止なら停止を維持する。背景化・音声フォーカス喪失・使用中の出力切断を記録し、その後の閉じるでは再開しない。file／content URIのアクセス失効やプレイヤーエラーでも再開しない。表示中と閉じた後の復元待ちではPlay要求を拒否し、背後の再生を始めない。

情報表示中は操作部を隠す。TVはOKへフォーカスし、通常の一時停止から開いた場合は閉じた後に元のボタンへ戻す。割り込み後は再生ボタンでの手動再開を待つ。通常の回転でも退避状態を維持する。情報画面を閉じる／セッションを終了する場合は取得ジョブをキャンセルし、遅れた結果が別セッションへ表示されたり、閉じた画面を再び開いたりしないよう保持状態を照合する。

音声出力名はAudioManagerの出力一覧から最初のUSB・Bluetooth A2DP・有線ヘッドホン／ヘッドセットを選び、該当がなければBuilt-in Speakerと表示する。プレイヤーが実際に使用している出力経路を取得した結果ではない。

## 5. 操作仕様

画面・読み上げ・ツールチップの共通名称は「ホームに戻る」「ファイル一覧」「メディア情報」「再生」。登録は「このフォルダーを登録」、親階層は「上のフォルダー」、選択全体の取消は「キャンセル」とする。「ホームに戻る」は再生終了、「ファイル一覧」は一時保持付き選び直しとして区別する。フォルダー登録・キャンセル・親階層・再読み込みの共有ボタンは文字が折り返される場合に高さを広げ、最小48dpを保つ。

### 5.1 タッチ操作

| 操作 | 動作 |
|---|---|
| シングル/ダブルタップ：左1/3 | 10秒巻き戻し |
| シングル/ダブルタップ：中央1/3 | 再生 / 一時停止 |
| シングル/ダブルタップ：右1/3 | 10秒早送り |
| 右スワイプ | 前のファイル |
| 左スワイプ | 次のファイル |

単指のスワイプはACTION_DOWNからACTION_UPまでの移動量を使い、横移動70dp以上、かつ横移動が縦移動の1.5倍以上の場合に判定する。画面密度からpxへ換算し、境界の70dp・1.5倍を含める。速度やGestureDetectorのonFling通知は条件にしない。右は前のファイル、左は次のファイルへ1回だけ移動し、元の再生／一時停止の意図を維持する。

ActivityでViewGroupが入力を部品別に分割する前の指の本数を確認する。2本目が操作ボタン上に加わった場合もメディア側のGestureDetectorをキャンセルし、残る1本が動いても同じ入力列ではタップ・曲送り・シークを実行しない。ACTION_CANCEL、回転、ウィンドウフォーカス喪失、背景化、セッション終了でも入力途中の状態とタップの重複判定を破棄する。次の新しいACTION_DOWNから通常の入力を再開する。

スワイプが成立した場合やOSのtouch slopを超えて動いた場合は、タップ検出をキャンセルして二重実行を防ぐ。ダブルタップの2回目のDOWNからスワイプへ変わる場合も、離す前にはタップ操作を実行しない。初回タップはGestureDetectorのonSingleTapUpで、指を離した時点に実行する。onSingleTapConfirmedの確定待ちは使わない。

直前に実行したタップと同じ3分割領域・近い位置への追加タップは、直前のUPから次のDOWNまで300ms以内なら追加実行しない。距離はOSのscaledDoubleTapSlopを半径とする2次元距離で判定し、時間・距離の境界を含める。OSのgetDoubleTapTimeoutが300msより長ければその値を使う。別領域または許容距離外のタップはすぐに受け付け、新しい基準にする。抑制したタップで時間を延長しない。スワイプ・多指・取消・画面の中断に加え、画面ボタン・再生ショートカットの実行で重複判定をリセットする。

OSのtouch slop・長押し判定はGestureDetectorに従い、長押しをタップに変えない。独自の入力遅延や設定項目は追加しない。実機のタッチ感度やアクセシビリティ生成入力は別途受入確認が必要。

### 5.2 リモコン・キー操作

再生画面の `dispatchKeyEvent()` で共通のキー割当を処理する。独自コマンドは最初のACTION_DOWNだけで実行し、同じdeviceId・keyCode・downTimeに属するリピートとキーアップも消費する。一時停止でTVのフォーカスが再生ボタンへ移った後にキーアップが届いても、同じ押下で再開しない。キー処理自体はTV判定で限定しない。

| キー | 再生領域 | ボタン等の部品にフォーカスがある場合 |
|---|---|---|
| Space | 再生 / 一時停止 | 部品の標準処理 |
| 決定 / Enter / テンキーEnter / A | 再生 / 一時停止 | 選択したボタンを実行 |
| D-pad左 / 右 | 前 / 次のファイル | 標準フォーカス移動 |
| D-pad上 / 下 | 10秒戻す / 進める | 標準フォーカス移動 |
| Shift＋左 / 右 | 10秒戻す / 進める | 部品の標準処理 |
| MEDIA_PREVIOUS / NEXT | 前 / 次のファイル | 同じ |
| MEDIA_PLAY_PAUSE | 再生 / 一時停止 | 同じ |
| MEDIA_PLAY / PAUSE | 明示的に再生 / 一時停止 | 同じ |
| MEDIA_REWIND / FAST_FORWARD | 10秒戻す / 進める | 同じ |
| INFO / I | 一時停止して情報ダイアログを開く | 同じ |
| Esc / O | 再生元のファイル一覧 | 同じ |
| H | 再生セッションを終了してホーム | 同じ |
| Tab / Shift＋Tab | 標準の部品間移動 | 標準の部品間移動 |

Shift＋左右以外の独自コマンドは修飾キーなしだけを対象にする。Ctrl・Alt・MetaやShiftとの複合修飾は標準処理へ渡し、OS・部品の操作を優先する。音量キーは独自に処理しない。文字入力部品にフォーカスがある場合も標準処理へ渡し、I・O・H・Space・Backspaceや矢印を再生コマンドにしない。スマホでも再生領域をキーボードのフォーカス対象とし、非タッチ操作で操作部を隠した後は再生領域へフォーカスを戻す。

一覧・情報ダイアログのキーはそのウィンドウで処理し、Activityの独自ショートカットはウィンドウが入力フォーカスを持つ場合だけ実行する。共有一覧・情報・エラー等の標準ダイアログはメディアの再生・一時停止・前後・シーク・停止・ヘッドセットキーを消費し、背後のプレイヤーやOSのメディアキー処理へ流さない。矢印・決定は最前面の部品・リスト・スクロールを操作する。音量キーは標準処理へ渡す。

PlayerControllerはMediaSessionのonConnectとsetAvailableCommandsで外部コマンドを制限する。一覧・情報の退避／復元中、エラー画面、前面の別ウィンドウ、文字入力欄へのフォーカス中は、メディア情報・タイムライン等の取得と音量操作だけを許可する。再生／一時停止、シーク、前後送り、停止、準備、キュー変更、再生速度・リピート等を拒否する。接続済みのMedia3／platform controllerと、制限中に新規接続したcontrollerの両方に適用し、onMediaButtonEventでも同じ状態のメディアボタンを消費する。

標準ダイアログは表示前に登録して、ウィンドウのフォーカス通知が届く前から外部操作を制限する。閉じる際に登録を解除し、セッション終了時も残るダイアログを閉じる。フォーカス・ウィンドウ・退避状態の変化で許可を更新し、モーダルを閉じて入力可能になると外部操作を再び許可する。一覧・情報では非同期の保持状態復元が終わるまで制限を維持する。復元用の内部seek／playは独立して実行し、前面ウィンドウが閉じる途中でもD01・D06の状態復元を妨げない。画面操作用の再生切替・シーク・前後送りヘルパーにも入力状態を確認し、遅れて届くジェスチャー処理などによる背後の操作を抑止する。通常のウィンドウフォーカス喪失だけでは再生を一時停止しない。背景化時の一時停止・明示再開の扱いは従来どおりとする。

一覧のEscは階層にかかわらず選択全体をキャンセルする。BackspaceはAndroidの戻ると同じ処理を呼び、親階層へ1回移動する。親がない最上位ではキャンセルする。読み込み待ち中は戻ると同じく選択をキャンセルする。Backspaceのリピート・キーアップでは追加の階層移動をせず、修飾付きのBackspaceは独自処理しない。入力欄では通常の文字削除を優先する。ファイル一覧のリストがフォーカスを持つ場合、Page Up／Downは左右キーと同じ可視行数に基づくページ移動とし、端では循環・ツールバーへの移動を起こさない。情報画面のI／Esc／戻るは情報だけを閉じ、同じ入力で一覧を開かない。

### 5.3 マウス・トラックパッド

SOURCE_MOUSE・SOURCE_TOUCHPAD、またはマウスのツール種別をポインター入力として識別する。マウスソースで指のツール種別を報告するトラックパッドも含め、直接タッチの3分割操作と区別する。

- 背景の主ボタンクリックは位置によらず再生／一時停止。近い位置のダブルクリックはタップと同じ時間・距離条件で1回分にする。全画面切替は行わない。
- 主ボタン以外、複数ボタン、ドラッグ、2本指スワイプ・ピンチの分類、ホイールを再生操作へ変換しない。移動がOSのtouch slopを超えれば、戻ってから離してもクリックにしない。
- 画面ボタンは通常のクリックとして対応操作を実行する。操作部の表示はDOWNのヒットテスト後に行い、新しく表示されたボタンが背景への押下を奪わないようにする。
- 非アクティブなウィンドウを有効にする最初のクリックは全体を消費する。DOWNの配送前にフォーカス取得通知が来る場合も、入力時刻と通知時刻で識別する。
- ポインター移動で操作部とカーソルを表示する。動画を再生する意図がある間は3秒の無操作で非表示にし、再入力で表示する。操作部のフォーカス、ボタン上、押下中、タッチ探索が有効な間は自動非表示にしない。ダイアログ・背景化・回転・セッション終了ではタイマーと古い入力を破棄し、カーソルを復元する。
- 音声のみの再生は常時操作部を表示し、終了・エラー・タッチ探索と同様、映像用の自動非表示を適用しない。
- 一覧のファイル・フォルダーは標準の1クリック選択、ホイールはListViewのスクロールを使う。右ボタンはファイルの再生にせず、登録先では長押しと同じ登録解除等のコールバックを実行する。通常の読み上げクリック・長押しも維持する。

## 6. Android TV対応

- 同一MainActivityを通常の `LAUNCHER` と `LEANBACK_LAUNCHER` に登録。
- `android.software.leanback` と `android.hardware.touchscreen` はともに `required=false`。
- TV判定はConfigurationの `UI_MODE_TYPE_TELEVISION`。
- TVホーム用バナーをApplicationの `android:banner` に指定。
- TV専用Activityはなく、共通レイアウトと横画面向け寸法を使用する。画面方向の固定指定はない。
- 最低OSはTVもAPI 34。古いTV OSへの互換対応は実装していない。
- TVでも「端末 / SAFのフォルダー」は `OpenDocumentTree` でシステムのフォルダー選択を起動する。「USB / 外部ストレージを選ぶ」は別項目としてアプリ内のUSBブラウザーを開く。
- SAFの起動要求でActivityNotFoundExceptionが発生した場合は、選択画面を開けない旨を表示し、ユーザーがUSBの選択を選んだ場合だけUSBブラウザーへ進む。

### 6.1 USBブラウザー

- 対象：Nebula X1など、システムのフォルダー選択アプリを利用できないTVでのUSB再生。
- 「すべてのファイルへのアクセス」が必要。共有ストレージ全体への読み書きが可能になる許可であることを説明し、ユーザーが設定を開く操作を選んだ場合だけOS設定へ進む。実装は読み取りのみ。
- アプリ個別のアクセス許可設定を開き、起動できなければ全アプリの許可一覧を試す。どちらも起動できなければ手動設定の案内を表示する。
- 設定画面から戻った際に許可を再確認。許可済みなら一覧を開き、拒否された場合は案内して終了する。
- StorageManager.storageVolumesから、取り外し可能かつマウント済み（読み取り専用を含む）のストレージを列挙する。OSにマウントされていないUSBには対応しない。
- ドライブ一覧・フォルダー追加・読み込み・エラー画面にもSAF・DLNAと共通のDlnaSelectionDialogを使用する。暗色背景、アイコン付き行、上部の戻る・キャンセル・再読み込みを統一し、追加時の「このフォルダーを登録」は下部に表示する。階層移動・再読み込み・保存済み一覧への登録完了では同じウィンドウを維持する。画面回転時は縦横レイアウトを更新する。
- ダイアログの一覧をD-padで操作。追加時はフォルダーを先に名前順、次に対応メディアをOP/ED順で表示する。登録済みのファイル選択はフォルダーを季節順、対応メディアをOP/ED順で表示する。
- フォルダーを開いた画面に「このフォルダーを登録」を表示する。現在のドライブのルートとフォルダーの正規化パスを登録し、保存済み一覧のその行へ戻る。追加用USBブラウザーのキャンセルは保存済み一覧へ戻り、OSのアクセス許可要求をキャンセルした場合は追加先選択を維持する。同じフォルダーの再登録では重複しない。空フォルダーも登録できる。保存済みのUSB項目はDLNA・SAFと同じファイル選択ダイアログで登録先を直接開き、未許可ならOS設定で許可を求める。登録後のファイル選択画面には「このフォルダーを登録」や登録解除ボタンを表示しない。登録解除は保存済み一覧の各行にある「その他」→「登録解除」から行う。長押し・右クリックも補助操作として使用できる。取り外し・削除・読み取り不可の場合はエラーを表示し、登録は保持する。
- 「上のフォルダー」または戻るキーで親へ移動し、ルートからはドライブ一覧へ戻る。「キャンセル」で閉じる。
- 親へ移動すると、直前の子ディレクトリを親一覧内で選択し、表示位置までスクロールする。ドライブ一覧へ戻ると元のドライブを選択する。対象が削除・取り外し済みの場合は先頭行に戻す。一覧表示後のフォーカス復元は、そのダイアログがまだ表示中の場合だけ行う。
- 読み取りに成功したドライブのルートとフォルダーの正規化パスをSharedPreferencesに保存し、ブラウザー再表示・アプリ再起動後に復元する。接続中のドライブと一致し、そのルート配下で読み取れるディレクトリの場合のみ復元する。USB未接続・パス変更・フォルダー削除・読み取り不可の場合はドライブ一覧に戻り、保存値は次の成功した閲覧まで保持する。明示的なルートからの「戻る」や一覧の再読み込みでは復元を行わない。
- ディレクトリ探索はドライブのルート内に制限。IO処理はバックグラウンドで実行し、読み込み中のキャンセルとActivity破棄時の解放に対応する。
- ファイルを選ぶと、そのフォルダー直下のプレイリストをfile URIで再生する。ファイルのコピー・削除・書き込みは行わない。
- 選択したファイルはRandomAccessFileで開き、空ファイルでないことと先頭・末尾の1バイトを読めることを確認してから再生へ進む。これはコンテナー形式やコーデックの再生可否を保証する検査ではない。
- USB未接続、空フォルダー、読み取り失敗、権限拒否には案内を表示する。
- Nebula X1実機でのUSB認識、許可画面、再生は別途確認が必要。

## 7. ファイル選択・スキャン・並び順

SAF・USB（追加時を含む）・DLNAのファイル選択一覧では、メディアファイル名の末尾の既知の拡張子を表示タイトルから除く。拡張子は大文字小文字を区別せず、DLNAの拡張子なしタイトルや名前の途中のピリオドは保持する。フォルダー・サーバー・保存済みフォルダー名にはこの処理を適用しない。省略後の名前が同じメディア同士、またはフォルダー名と重なる場合は、メディア行にMP4・M4Vなどの形式バッジを表示する。形式は既知の末尾拡張子、既知の拡張子がない場合は認識可能なMIME typeから取得し、判定できなければ「不明」とする。コーデックや端末での再生可否を推定する表示ではない。元のVideoItem.displayName、URI、並び順、選択インデックスは変更しない。

一覧の「名前・形式」で選択中の項目のメディア情報を開く。行の長押し・右クリックからも開ける。元の名前の全文、形式、取得済みのMIME typeをスクロール可能な画面に表示し、行のツールチップと読み上げにも元の名前と形式を含める。閉じる・戻る・Escで元の一覧の選択行へ戻り、この操作では再生しない。再生中に一覧を開いた場合も、確認画面を開閉する間は元の再生位置・キュー・一時停止を保持し、一覧全体のキャンセル時に再生状態を復元する。高さ700dp未満・文字倍率150%以上のファイル選択では補助説明を非表示にして一覧領域を確保する。空の一覧には名前確認ボタンを出さず、取得中は無効にする。一覧更新・ブラウザー終了時には古い情報画面も閉じる。

共通ダイアログは初回表示・内容更新の両方で読み込み状態を操作無効化に反映する。取得中は行の決定・長押し・右クリック・親移動・再読み込み・登録・名前確認を無効にし、キャンセルを利用できる状態に保つ。初回読み込み時のフォーカスはキャンセルに置く。取得中の戻る／Backspaceは親階層へ移動せず、キャンセルと同じ処理で要求を取り消す。追加用ブラウザーのキャンセルは既存の登録フローと同じ保存済み一覧へ戻り、通常のファイル選択はブラウザーを閉じて元の再生状態の復元へ進む。キャンセル後に遅れて届いた成功・失敗応答は画面へ反映せず、古い行のコールバックやフォーカス処理も拒否する。

### 7.1 SAF選択フロー

SAF・USB（ドライブ一覧・追加時を含む）・DLNAの共通ファイル選択ダイアログでは、一覧にフォーカスがある時のD-pad左をPage Up、右をPage Downとして処理し、表示ページ単位で選択位置と一覧を移動する。上下は1項目ずつ選択し、決定で開く・再生する。先頭・末尾では左右を押しても一覧のフォーカスを維持する。取得中はページ移動を無効にする。ツールバーの左右は従来どおりボタン間のフォーカス移動に使う。保存済み一覧・サーバー一覧・追加先選択にはページ操作を適用しない。

1. ホームの「OP / EDを選ぶ」は、保存済みが0件・1件・複数件のいずれでも保存済みフォルダー一覧を開く。0件では空の案内と「フォルダーを追加」を表示し、追加ボタンを初期フォーカスとする。追加する再生元は、このボタンを明示操作して選ぶ。「フォルダーを追加」の再生元選択もSAF・DLNAと共通のダイアログとアイコン付き行を使用し、画面回転時に縦横レイアウトを更新する。保存済み一覧から追加先選択への切り替えは既存ウィンドウの内容を更新し、トップ画面へのフラッシュを防ぐ。追加先選択のキャンセル・戻る・Escは、保存済みが0件でも保存済み一覧へ戻る。端末 / SAFを選ぶとTVでも `OpenDocumentTree` を起動する。TVの追加先にはSAF・USB・DLNAの3項目を表示する。
2. ツリー選択後、読み取りの永続権限を取得して保存済み一覧へ戻り、登録したツリーの行を選択・表示する。重複登録でも既存行を選択し、登録だけではフォルダーを開いたり再生したりしない。永続権限の取得に失敗した場合は通知し、追加先選択を維持する。標準ピッカーのキャンセルも追加先選択へ戻る。
3. 読み取りの永続権限を持つツリーURIを保存済みSAFとして扱う。SAFだけで1件の場合も、USB・DLNAと共通の保存済みフォルダー一覧に表示し、行を明示選択するまでフォルダーを開かない。先にSAFをDLNAと共通の季節順（同じシリーズごとに年の昇順、冬→春→夏→秋）、次にDLNAの登録をサーバー名＋フォルダー名の文字列順で表示する。SAFには「端末 / SAF」、DLNAには辿った階層を補足表示する。ルートから一覧に戻り、「フォルダーを追加」でSAFまたはDLNAを選べる。USBは明示的に登録したフォルダーを末尾に季節順で表示し、「USB / 外部ストレージ」とパスを補足表示する。最後に閲覧しただけの位置は一覧に含めない。
4. DLNAと共通のダイアログ・行レイアウトを使用する。フォルダー優先で、フォルダーはDLNAと同じ季節順、対応動画・音声は共通のOP/ED順に並べる。
5. `DocumentsContract` でツリー内の子ドキュメントをIOディスパッチャー上で取得する。document IDは不透明な識別子として扱い、パスの解析は行わない。親への移動は辿ったフォルダーのスタックで管理する。
6. 選択したファイルを含むフォルダー直下の対応ファイルをプレイリストとし、選択位置から連続再生する。システムの `OpenDocument` は使用しない。
7. 初回の読み込み中・空フォルダー・読取エラーを同じダイアログ内に表示する。ファイル一覧からの階層移動では現在の一覧を保ち、取得が0.5秒を超えた場合だけ読み込み表示を重ね、取得完了後に更新する。エラーから再試行やフォルダー一覧に戻る操作ができる。クラウド側で読み込み中の部分一覧は再試行を促し、未完成のプレイリストを作成しない。
8. 戻るボタンは親フォルダー、ルートでは保存済み一覧へ移動し、「キャンセル」はファイル選択を終了する。親では直前の子フォルダー、保存済み一覧では元のSAFルートを選択してスクロールする。画面回転時は共通ダイアログの縦横レイアウトを更新する。
9. 再生開始時とActivity停止時に最後の再生元フォルダーの識別子をSharedPreferencesへ保存する。次回の保存済み一覧では該当項目へスクロールする。SAFはツリーと再生元までの各階層のURIを保存し、保存済み一覧では元のツリー、ツリー内のファイル一覧では再生元へ続く子フォルダーを選ぶ。SAFが1件の場合も、保存済み一覧で元のツリーを選択し、その行を開いた後にツリー内の選択位置を復元する。DLNAでは同じサーバーの最も近い登録済み祖先を選ぶ。並び順や名前が変わっても識別子で照合する。USBでは同じドライブ内の最も近い登録済み祖先を選ぶ。該当項目が削除・登録解除済みの場合は先頭を表示する。再生せずに終了しても保存値を保持し、親から戻った際の明示的な選択位置を優先する。

### 7.1.1 DLNAフォルダーの登録

- 追加用のDLNAブラウザーでは「このフォルダーを登録」を表示する。登録後はSAF・USBと同じ保存済み一覧へ戻り、サーバーID・フォルダーIDに一致する登録行を選択・表示する。重複登録も名称・階層を更新して既存行を選択し、登録解除には切り替えない。追加ブラウザーのキャンセル・探索／取得中の戻るは、要求を取り消して保存済み一覧へ戻る。サーバー一覧からも保存済み一覧へ戻れる。
- 保存済みフォルダーまたは再生元から開いたDLNAのファイル選択ダイアログには「登録」「登録解除」を表示しない。登録解除は保存済み一覧の各行の「その他」から確認を経て行い、新規登録は「フォルダーを追加」から開いたDLNAブラウザーで行う。
- DLNAのファイル選択ダイアログには「再読み込み」を表示し、現在のフォルダーの一覧を取得し直す。SAFのファイル選択ダイアログには表示しない。通信・読み取りエラー時の「再試行」は提供する。
- SharedPreferencesにサーバーID・サーバー名・ルートからのフォルダーIDとタイトルを保存する。キーはサーバーIDと対象フォルダーIDの組み合わせ。同じフォルダーを再登録した場合は名称・階層を更新し、重複しない。
- 登録先を開くとSSDPでサーバーを再検索し、サーバーIDで照合する。IP・controlURL・メディアURLは保存せず、現在のサーバー情報から対象フォルダーを列挙する。
- 保存済みから開いたDLNAでは、開いた登録先のサーバーIDとIDパスを閲覧境界とする。保存されているサーバー側の上位パスは識別・再接続用であり、親移動で登録先より上へは出ない。境界の戻るアイコン・Backspace・TV／Androidの戻るは保存済み一覧へ戻り、開いた登録先の行を選択・表示する。接続失敗時も同じ登録行への戻る操作と再試行を提供する。
- 保存済み行はフォルダーを開く領域と48dpの「その他」ボタンを分ける。「その他」→「登録解除」で、フォルダー名と「登録を解除しますか？ ファイルは削除されません。」を表示して確認する。キャンセルを初期フォーカスとし、キャンセル・戻る・Escでは登録を維持して元の行へ戻る。長押し・右クリックも同じ確認を開く補助操作とする。TVの左右／Tabで行内の開く領域とその他へ移動でき、読み上げでも別の操作として公開する。取得中は両操作を無効にする。
- 確認後はUSB・DLNAの保存登録だけを削除し、SAFは対象ツリーに保持する読み取り・書き込みの永続アクセス許可を解放する。他の登録先や実ファイルは変更せず、オフラインでも解除できる。再表示後は解除した行の次の項目、次がなければ前の項目、0件なら追加ボタンを選択・表示してフォーカスする。最後の再生先の記録は登録解除で書き換えない。再生中の一覧では元のPlayer・ファイル・位置・キューを保持し、保存済み一覧を閉じるまでは再開しない。
- サーバーID・フォルダーIDが変更された場合は、通常のDLNAブラウザーから登録し直す。

### 7.2 対象ファイル

- USB・SAF共通で、名前が `._` から始まるmacOSのAppleDoubleメタデータファイルを一覧・プレイリストから除外する。例：`._作品 OP.mp4` は除外し、`作品 OP.mp4` は対象とする。
- 両方式とも通常ファイルだけを対象にする。通常の隠しファイルは名前だけでは除外せず、対応拡張子なら対象とする。除外ファイルをストレージから削除・変更する処理はない。

- 選択ファイルの親ディレクトリ直下のファイルを列挙する。
- ブラウザーで開いたディレクトリだけを列挙し、配下の再帰スキャンは行わない。
- 拡張子は大文字小文字を区別せず、以下を対象とする。

`.mp4`, `.m4v`, `.mp3`, `.flac`, `.m4a`, `.aac`, `.wav`, `.ogg`, `.opus`

拡張子での列挙対象と、端末で実際にデコードできる形式は別である。

### 7.3 OP/EDの並び順

1. 全ファイルを端末の既定LocaleのCollator（SECONDARY）で名前の昇順に並べる。
2. 拡張子を除いた名前が `^(.+?)\s+(OP|ED)(\d*)$` に一致するものを抽出する（大文字小文字を区別しない）。
3. OP/EDより前のベース名でまとめ、番号の昇順、同番号ではOP→EDの順にする。番号省略は1として扱う。
4. 各グループが元々占めていた位置だけを入れ替える。非該当ファイルの位置は維持する。

例：同一作品の該当ファイルは `作品 OP → 作品 ED → 作品 OP2 → 作品 ED2` の順となる。本編をOPとEDの間に挿入する処理はない。

開始位置は独自ブラウザー上で選んだメディアのインデックスをそのまま使用する。

## 8. 再生と状態管理

- ExoPlayerへURIのMediaItem一覧を渡し、選択位置の0msからprepare・playする。
- リピートはOFF。次の項目へ自動遷移し、最終項目で終了する。
- 最終終了では古いplayWhenReadyをfalseにして、後のシークだけで自動再生しない。終了したメディアと位置を保持し、一覧・情報のキャンセルでネイティブ状態がREADYに戻った場合も、完了表示と0秒からの再開を維持する。別項目への移動や終了位置以外への明示シークでは完了を解除する。
- 再生／setPlayWhenReady(true)の共通入口で、一時表示による制限と音声フォーカスを確認してから、終了状態なら同じ項目の0msへ戻して再生する。画面・タッチ・キーボード・TV決定・MediaSessionのいずれも同じ扱いとする。
- 前後移動は該当項目と対応コマンドがある場合だけ移動先の0msへ進み、元の再生／一時停止意図を維持する。先頭の前・末尾の次は何もしない。MediaSessionのPreviousでも現在ファイルの先頭へ戻す例外は使わず、前のファイルへ移動する。
- 巻き戻しは0ms未満にならない。早送りで既知の再生時間の末尾以上へ達する場合、次の項目があれば0msへ移動し、なければ現在位置と再生意図を変えない。時間・位置の加算はオーバーフローを防ぐ。
- ±10秒はタッチ・キー・画面ボタン・MediaSessionで同じ幅とする。現在項目のシーク可否とSEEK_IN_CURRENT_MEDIA_ITEMおよび方向コマンドの可否を確認し、不可なら移動しない。現在項目への絶対位置・デフォルト位置のシークも可否を確認する。別ファイルへの選択は別の操作として許可する。
- 長さ不明でもシーク可能なら、次のファイルを推測せず現在項目内のシークをエンジンへ渡す。MediaSessionへ通知する操作可否もシーク可否・前後の有無に追従させ、モーダル中の読み取り・音量以外の制限を維持する。
- 独自の先読み・クロスフェード・ギャップレス保証はない。

### 8.1 エラー処理

スマホ／TV、ローカルファイル／USB／SAFのcontent URI／HTTPの区別なく、再生失敗では同じPlayer・失敗項目・プレイリストを保持して一時停止する。UIコールバックを設定していないPlayerControllerでも停止する。エラー回数によるスキップ・自動prepareは行わず、通信や接続が回復しただけでは再試行・再開しない。

ファイル名・エラー名と数値コード・最大5段の例外情報をダイアログで表示する。現在の操作は「再試行」「別のファイルを選ぶ」「キャンセル」。「再試行」は同じプレイヤーでprepare・playし、「キャンセル」は表示だけを閉じて停止を維持する。4操作への整理、最後の確認位置からの再試行、原因別の再許可／再接続案内はD26で扱う。

背景化中、ファイル選択・情報表示／復元中、別のダイアログが前面にある場合は停止を先に適用し、再生画面のフォーカスが戻ってから案内する。一覧・情報の退避状態は割り込み済みとし、キャンセルしても自動再開しない。失敗中の古い位置へシークしてエラーを消さず、プレイヤーの失敗位置を保持する。待機中のエラーはコントローラー・項目・インデックスに結び付け、別の項目選択・新しいセッション・ホーム・終了で破棄する。

操作部の「フォルダー選択」、スマートフォン・Android TVの戻るキー、または修飾なしのEsc／Oを押すと、再生セッションを保持して一時停止し、再生元フォルダーのファイル選択ダイアログを開く。停止前の現在の再生項目を指定して画面内にスクロールし、TV・キーボード操作ではカーソルも合わせる。一覧ボタンも戻る／Esc／Oと同じ現在ファイル指定の処理を使う。連続再生で進んだ場合も、その時点のファイルを対象とする。SAF・USBはURI、DLNAはサーバー内のオブジェクトIDで照合し、表示名の重複やDLNA接続先URLの変更に影響されない。フォルダー行を含む一覧の位置へ変換し、対象ファイルがなくなった場合は先頭へ戻す。一時停止中も同じ動作。ホーム画面の戻るはOSへ委譲し、バックグラウンド化後にアプリへ戻った場合にも再生画面の戻る処理を再び利用できるよう、コールバックの有効状態を維持する。

操作部の「フォルダー選択」とスマホ・TVの戻る／Esc／Oでは、プレイヤー・MediaSession・音声設定を解放しない。選択開始時のプレイリスト・再生元フォルダー・ファイルのインデックス・秒数・playWhenReadyを一時保持する。階層移動、登録操作、SAF／USB／DLNA間の一覧切り替えでは変更せず、選択全体のキャンセルで同じプレイヤーの元の位置・状態へ戻す。ホーム画面は挟まない。ファイルを選択した場合は保持状態を破棄し、選択先の0秒から新しいセッションで再生する。ホーム・終了・Activity破棄でも保持状態を破棄する。

一覧を開く間はシステムバーを表示し、背後の再生画面へのフォーカス復帰通知では全画面表示を再適用しない。キャンセルして再生画面へ戻ると全画面表示へ戻す。セッションの保持とウィンドウの表示状態を分けて扱い、TVの一覧フォーカスと読み上げを維持する。

一覧表示中のonStopを記録し、その後のキャンセルでは再開せず操作部を表示する。ファイル選択中にMediaSession等がplayを要求しても一時停止を維持する。キャンセル時には元のfile／content URIをIOスレッドで開けるか確認し、アクセスを失ったローカルメディアをキャッシュだけで自動再開しない。アクセスできない場合は接続と権限の確認を案内する。DLNAの接続断の検出・再接続は既存の再生エラー処理の対象で、一覧キャンセル時にHTTP到達性の検査は行わない。

「別のファイルを選ぶ」と操作部の「フォルダー選択」、およびスマホ・TV再生画面の戻る／Esc／Oは、現在のプレイリストを選んだフォルダーへ直接戻る。SAFはツリー内の階層、USBはドライブとディレクトリ、DLNAはサーバーIDと階層をViewModelに保持する。DLNAは最新の接続先を検索して同じフォルダーIDを開き、保存済み登録の有無には依存しない。画面再生成でもフォルダーを保持する。再生元情報がない場合は通常の選択フローへ進む。

`ERROR_CODE_PARSING_CONTAINER_UNSUPPORTED (3003)` はコンテナー形式を解析できなかったことを示す。AppleDoubleの `._` ファイルは列挙対象から除外しているが、動画本体で発生した場合はコンテナー形式や読み取り状態を別途調査する。

### 8.2 ライフサイクル・保存範囲

- `onStop()`：再生セッションがある場合は、同じプレイヤーのまま一時停止し、復帰後の手動再開待ちにする。ファイル・インデックス・秒数・プレイリストはプレイヤーに保持する。ファイル選択中・情報表示中なら割り込みを記録する。
- `onStart()`：自動でplayしない。停止していたセッションでは、現在のファイル名と再生操作部を表示する。ファイル選択中・情報表示中は操作部を隠し、割り込み後のキャンセル／閉じるでも一時停止を維持する。再開は再生ボタン・中央タップ・決定・メディア再生キー等の明示操作で行う。
- `onDestroy()`：プレイヤー、MediaSession、音声設定を解放し、再生画面フラグをfalseにする。
- Manifestでorientation・screenSize・keyboardHiddenの構成変更をActivity自身が処理する。
- `onPause()`やウィンドウフォーカス喪失だけでは停止しない。可視状態のフォーカス移動、通常の回転・サイズ変更では同じプレイヤーと再生／一時停止状態を維持する。TVの復帰時は再生ボタンにフォーカスし、決定による再開後は再生領域へ戻す。
- ViewModelはメモリー内のプレイリスト、再生画面フラグ、再生元フォルダー（PlaybackFolder）を保持する。再生停止でもプレイリストと再生元情報を消去しない。
- ファイル選び直し・情報表示中の位置・選択インデックス・再生意図はActivity内で一時保持する。永続保存、SavedStateHandle、プロセス終了後のプレイリスト復元は実装していない。
- Activity再生成後の再生復元分岐はあるが、onDestroyのstopPlaybackで画面フラグがfalseとなり、startPlayback内でもリセットするため、再生の継続復元は保証されない。再生元フォルダーの保持とは別の制約である。
- SAFのアクセス権限、登録済みDLNAのIDと階層、USBの登録済みフォルダーと最後に読めた閲覧位置を永続保存する。これらは再生位置・履歴の保存とは別。
- バックグラウンド再生サービスはない。

### 8.3 音声フォーカス・出力切断

`PlaybackAudioMonitor`がUSAGE_MEDIA／CONTENT_TYPE_MUSICのAudioFocusRequestを管理する。音量低下要求にも一時停止で応じるためsetWillPauseWhenDucked(true)を指定し、遅延取得による自動再開は要求しない。Media3の自動音声フォーカス制御は無効にする。

PlayerControllerはPlaybackTransportPlayer（ForwardingPlayer）を画面・操作・MediaSessionに共通で渡し、play／setPlayWhenReady(true)の前にフォーカス取得を確認する。拒否された場合は一時停止を維持する。恒久・一時喪失・音量低下要求では同じプレイヤーを一時停止し、ファイル・位置・キューを保持して操作部を表示する。フォーカス取得通知だけではplayしない。一覧表示中・情報表示中のPlay要求は、フォーカスを要求する前に拒否する。

一時停止や一覧・情報への一時移動では生存中のセッションのフォーカス監視を保持し、表示中の割り込みも記録する。キャンセル後や情報画面を閉じた後も自動再開しない。背景化では一時停止してフォーカスを返し、明示的な再開時に取り直す。セッション終了ではフォーカス、受信機、機器・経路コールバックを解放する。

出力切断は、システムのAUDIO_BECOMING_NOISYとAudioDeviceCallbackを監視する。Media3標準のAudioTrack生成処理を委譲先として使い、AudioRoutingの通知で実際の出力IDを追跡する。使用中の出力IDが削除された場合は一時停止し、別の接続機器の取り外しでは停止しない。経路が先に内蔵スピーカーへ切り替わった場合も、直前の出力が消失したことを確認する。AudioTrackの経路がまだない間はAudioManagerのメディア出力候補を使用する。再接続や経路の更新は再生指示として扱わない。

Media3は既存common-ktxの指定に合わせ、すべて1.9.2の同じバージョン参照へ統一する。以前の1.5.1との混在ではコンパイル時と実行時でAudioTrackProviderのシグネチャが異なっていた。

## 9. USBビットパーフェクト音声設定

`BitPerfectAudioManager` がUSB出力に対して対応ミキサーの設定を試みる。

1. USB_DEVICEまたはUSB_HEADSETの出力デバイスを探す。
2. BIT_PERFECT対応ミキサー属性を取得する。
3. MediaExtractorで再生開始ファイルのサンプルレート・チャンネル数を抽出する。
4. 両者が一致する属性を優先し、なければ最初のBIT_PERFECT属性を選ぶ。
5. USAGE_MEDIA / CONTENT_TYPE_MUSICでsetPreferredMixerAttributesを実行する。
6. 成功時はactiveDeviceを保持。解放時にclearPreferredMixerAttributesを呼ぶ。

非対応デバイスや設定失敗時は設定を適用しない。処理は例外をログに記録する。

設定はプレイヤー生成時の開始ファイルについて実行される。項目切り替えごとの再設定はない。表示上の「Bit-Perfect」は設定成功状態を表し、実出力のビット一致を測定した結果ではない。HDMIなどを含むすべての出力経路でのビットパーフェクト動作は保証しない。

設定とMediaExtractorによる情報抽出はIOディスパッチャーで行い、設定完了を待たずに再生を開始する。フォーマットを抽出できなければ設定を行わない。USBの接続・取り外しによる自動再設定はない。

## 14. DLNAクライアント

- 「サーバー一覧」に「アドレスを指定して接続」を常設し、自動探索中も利用できる。マルチキャスト可能な稼働中インターフェースがない場合は自動探索を開始せず、探索エラーの場合も「この環境ではアドレスを入力して接続してください」と案内する。入力へ進む際は探索ジョブを取り消し、遅い探索結果で入力画面を上書きしない。
- 手入力はIPアドレス・ホスト名、またはDLNA機器情報のhttp / https URLを受け付ける。ホスト名・IPだけの場合はその相手のUDP 1900へユニキャストM-SEARCHを約4秒、約1秒間隔で送信し、返されたLOCATIONを取得する。URLの場合はSSDPを使わず機器情報を直接取得する。URLのパスやポートを含む入力はhttpの省略にも対応する。機器情報にContentDirectoryがあることを検証してフォルダーを取得する。Web管理画面のURLをDLNA機器情報としては扱わない。
- 入力画面も同じウィンドウとコンパクトな上部操作部を使用し、入力値とカーソル位置を構成更新後も保持する。Enter／IMEの完了／「接続」で送信し、接続中は入力・重複送信を無効化してキャンセルを維持する。失敗後は入力を残して「再試行」を表示する。Backspaceは編集中の文字削除に使い、待機中の戻るはサーバー一覧（登録先の再接続では保存済み一覧）へ、接続中の戻るはD22と同じキャンセルへ進む。
- 手入力で機器情報とサーバーIDの確認に成功したURLは、saved_dlna_foldersのサーバーID別キーに保存する。フォルダー登録のID・パスのJSONは変更せず、接続だけではフォルダーを自動登録しない。このURLがある登録先は次回から探索を経ずに直接接続し、同じサーバーIDを確認して元のオブジェクトID・現在ファイルを開く。URLがない既存の登録先は従来どおり探索する。接続失敗・ID不一致でも登録は削除せず、アドレスを修正して再試行できる。解除後も再生元への再接続に使用できるよう、接続先の記録は残す。
- ユニキャスト接続は[UPnP Device Architecture 2.0 §1.3.2](https://openconnectivity.org/upnp-specs/UPnP-arch-DeviceArchitecture-v2.0-20200417.pdf)のHOST指定・M-SEARCHに基づく。ホスト指定で応答しない機器は機器情報のURLを入力する。
- 対象はSynology「メディアサーバー」などのUPnP AV MediaServer。同一LAN内でSSDP M-SEARCHを約4秒間、約1.5秒間隔で送受信し、最大32件のLOCATIONからデバイス記述とContentDirectoryを取得する。探索後に記述を順次取得するため、全体の所要時間は4秒に限定されない。UDNで重複を除外し、UDNがない場合はLOCATIONをIDに使う。この場合はIP変更後の登録先照合を保証できない。
- オブジェクトID `0` をルートとし、SOAP BrowseDirectChildrenをRequestedCount=200で取得する。次ページの位置はフィルター後の件数ではなくNumberReturnedに基づく。同一ページの繰り返しや不完全な応答はエラーとする。
- DIDL-Liteのcontainerとitemを表示する。HTTP(S)・http-get・audio/video MIMEのリソースを再生対象とし、application/octet-streamまたはワイルドカードMIMEでは既存の拡張子判定を使用する。`._`項目は除外する。
- 動画・音声の一覧はVideoScannerの整列処理を共用する。VideoItemに任意のmimeTypeを追加し、MediaItemへ渡す。サイズ不明は-1、更新日時不明は0。
- フォルダーは名前順を基準に、同じ接頭辞・接尾辞の季節シリーズ内の位置だけをDlnaFolderSorterで整列する。年の昇順、同一年は冬→春→夏→秋。「YYYY冬」「YYYY年冬」「YYYYMM年冬」と季節の `*` / `_` 囲み表記を認識する。季節以外のフォルダーの位置とNAS上の名前は変更しない。
- DLNA選択画面は画面幅・高さとシステムバー領域に合わせた専用Dialog。最大幅880dp、高さは利用可能領域の92%・最大800dp。現在のフォルダー名、種類別アイコン、20sp・最大2行の名前を表示する。パス表示は省く。フォルダー・ファイル名の下に操作説明やサイズは表示せず、ファイル選択の縦画面では行の最小高さ48dp、上下余白各4dp、行間2dpとする。横画面では名前を1行表示とし、最小高さ40dp、上下余白各2dp、行間1dpに詰める。ファイル名の文字サイズは縦横とも20spとし、右端の矢印は横画面のみ24spにする。操作の説明はアクセシビリティの読み上げで提供する。サーバー一覧は接続先の識別用にアドレスを表示する。方向キーの選択は3dpのシアン枠で示す。初期選択は先頭項目。
- DLNAダイアログのサイズはウィンドウの表示前（onStart）に確定する。ウィンドウの拡大・縮小アニメーションは無効にし、読み込み・一覧・エラーの切り替え時も初期サイズから拡大する表示を行わない。
- 共通ダイアログの余白は通常20dp、横画面12dp。ファイル選択ではiOS版を参考に、戻るアイコン・キャンセル・現在のフォルダー名・再読み込みアイコン（DLNAのみ）を上部の一列に配置する。戻ると再読み込みは48dp角の丸いボタン、キャンセルは96dp幅の丸い横長ボタン。フォルダー名は18sp・1行の末尾省略で、ボタンの間の余った幅を使う。読み上げには省略前のフォルダー名と各操作の説明を残す。ボタン間のリモコンフォーカスは見た目と同じ順に移動する。ファイル行は左に丸枠の再生アイコンと名前を表示し、右端の矢印はフォルダー行にだけ表示する。縦画面の一覧の下には連続再生の説明を表示し、横画面では操作ヒントを非表示とする。画面回転時は選択位置（なければ先頭表示位置）を引き継ぎ、表示中のウィンドウでレイアウトとサイズを更新する。外側タップでは閉じない。
- ブラウザーを開いている間は同じダイアログのウィンドウを維持する。フォルダー移動・親へ戻る・再読み込み・読み込み完了・通信エラーでは内容だけを更新し、背後の初期画面が一瞬露出する閉じ直しを行わない。「戻る」による親移動もダイアログを閉じずに実行する。閉じるのはユーザーの明示的な終了、ファイル選択、Activity破棄時。画面回転時もウィンドウを維持してレイアウトを更新する。
- ファイル選択から再生へ進む際は、先に再生画面へ切り替えてプレーヤーを準備し、Activityの再生画面のフレームが描画・コミットされてからSAF・DLNAのファイルダイアログを閉じる。USBでも読取確認後の共通ファイル選択ダイアログを同じ描画完了まで維持する。初期画面を挟む表示を防ぎ、動画の最初のフレームを待つ間は再生画面の黒背景を表示する。
- DLNAブラウザーのフォルダー一覧では戻るアイコンは一覧上部の独立したボタン。「戻る」も親階層へ移動し、親へ戻った際には直前の子フォルダーへ表示・フォーカスを戻す。「キャンセル」はファイル選択を閉じる。追加用のブラウザーでは保存済み一覧へ戻り、再生中なら保持していたセッションの一時停止を維持する。保存済み一覧を閉じた時点で元の再生意図へ復元し、割り込み後は手動再開とする。選択した項目から同じ公開階層直下を連続再生する。初回の読み込み・空一覧・通信エラーも同じ画面で案内する。
- SAF・DLNAのファイル一覧表示後の階層移動・親移動・再読み込みでは読み込み画面に切り替えず、現在の見出し・一覧・スクロール位置を保持し、取得完了後に更新する。保存済み一覧からSAFフォルダーを開く際や、DLNAサーバー一覧からフォルダーを開く際も、読み込み画面を挟まず現在の一覧から取得後の一覧へ直接切り替える。取得中は古い一覧の選択、戻るアイコン、再読み込み、登録操作を無効にし、キャンセルまたは戻るキーでブラウザーを終了できる。回転時も取得中の操作無効状態を保持する。完了・エラー表示時に操作を有効に戻す。
- 保存済み一覧からDLNAフォルダーを開く際は、SAFブラウザーの表示中ウィンドウをDLNAブラウザーへ引き継ぐ。サーバー探索・一覧取得中も保存済み一覧を保ち、従来の検索中レイアウトを挟まずファイル一覧へ更新する。取得中の終了操作はDLNAの通信ジョブをキャンセルする。ルートから保存済み一覧へ戻る際もウィンドウを引き継いで内容を更新する。
- SAF・USB（追加・登録済みの双方）・DLNAの一覧を残して取得を行う場合、取得開始から0.5秒を超えたときだけ中央にシアンのローディングアイコンを重ねて表示する。縦画面は40dp、横画面は32dpとし、見出し・一覧・スクロール位置・ダイアログサイズを変えない。取得完了・エラー・キャンセル・次の要求開始時に表示と遅延処理を解除し、画面回転時は待機状態を維持する。初回の読み込み画面では通常の読み込み表示を直ちに出す。再生画面のフレーム描画待ちだけでは遅延アイコンを表示しない。
- 通常探索から開いたDLNAルートはサーバー一覧へ戻る。保存済みから開いた場合は開いた登録先を境界とし、その上はサーバーの親階層へ出ず保存済み一覧へ戻る。再生元から開くDLNA／USBの一覧は、現在の再生フォルダーを含む同じサーバー／ドライブの最も近い登録済み祖先を境界とし、該当がなければ現在のフォルダー自体を境界とする。DLNAの初回読み込み中は親移動を設定せず、戻るキーで要求を取り消す。追加中は保存済み一覧へ戻り、通常のファイル選択ならブラウザーを閉じる。SAF・USBの初回フォルダー読み込み中も親移動を実行せず、戻る／Backspaceはキャンセルと同じ経路で要求を取り消す。USBのドライブ一覧・フォルダー追加・登録済みUSB・USB再生元のファイル選択には共通のDlnaSelectionDialogを使用する。階層移動・再読み込み中は現在の一覧を保持し、読み込み完了後に更新する。登録ルートの「保存済みフォルダーへ」で同じウィンドウを保存済み一覧へ引き継ぐ。戻る登録先の識別子を返し、最後の再生先に関係なく直前に開いた登録行を選択して画面内へスクロールする。SAFの読取エラーから戻る場合も元のツリーを選択し、最後の再生先の保存値は一覧操作で書き換えない。画面回転時は共通ダイアログの縦横レイアウトを更新する。
- 通信はIOスレッドで行い、探索・ページ間でキャンセルを確認する。接続タイムアウト5秒、読み取りタイムアウト8秒、XML応答上限4MiB。一覧が10万件以上でさらにページがある場合はエラーとする。DTDと外部エンティティは拒否する。
- サーバー固有のログイン、SMB、DTCP-IP、キャスト、ブラウザー位置の永続保存は対象外。NAS実機での検出、フォルダー表示、連続再生、シーク、切断／再試行を別途確認する。
- DlnaProtocolTestでSSDPヘッダー、デバイス記述とURL解決、エスケープ済みDIDL、リソース選択、SOAP fault、外部エンティティ拒否を検証する。ローカルHTTPサーバーでページ分割とSOAPActionも検証する。
- DlnaSelectionDialogTestはサンプル一覧を使い、方向キーでの項目選択、戻ると閉じるの違い、横画面での操作を検証するAndroidテスト。NAS接続の実機検証とは区別する。

### 14.1 接続条件と確認事項

- DLNA一覧はNASの物理フォルダー一覧ではなく、メディアサーバーが公開する階層。Synologyでは「メディアサーバー」を起動し、「インデックスサービス」で対象フォルダーを動画／音楽のインデックス対象に追加して、作成完了を待つ。階層名はサーバー設定に依存する。
- NASが見つからない場合は、NASのファイアウォール、メディアサーバーのDMA互換性／デバイス許可、Wi-Fiの端末間通信制限を確認する。TVの有線LANも利用対象。
- シークやサイズ取得の可否はサーバーに依存する。サイズ情報がない場合は「サイズ不明」を表示する。
- 動的なLANアドレスへの平文HTTPをネットワークセキュリティ設定で許可する。HTTPでの配信は暗号化されない。
- Synology実機での検出・再生・シークは未確認。設定の参考：[Synologyのメディアサーバー設定](https://kb.synology.com/en-us/DSM/help/MediaServer/application_mediaserver_general?version=7)。
